# Proposal: LLM调用记录存储与展示

## 概述

为了更好地监控AI决策系统的运行情况、分析token消耗和优化提示词,需要将LLM的调用记录进行持久化存储,并提供全局的前端展示页面,支持分页、倒序显示和详细信息查看。

## 动机

当前系统已经有decision_logger记录AI的决策过程(包含system_prompt和user_prompt),但缺乏对LLM API调用本身的详细记录,包括:

1. **调用元数据**: 无法追踪每次API调用的时间、所属trader、使用的模型等基本信息
2. **Token统计**: 缺少输入/输出token的详细统计,无法分析成本
3. **响应时间**: 未记录API响应时间,难以发现性能问题
4. **历史查询**: decision_logger基于文件存储,不支持高效的分页查询和过滤
5. **全局视图**: 无法在一个页面查看所有trader的LLM调用情况

## 目标

1. **后端存储**: 在数据库中新建表存储LLM调用记录
2. **调用拦截**: 在mcp.Client中记录每次LLM API调用的详细信息
3. **API接口**: 提供RESTful API供前端查询LLM调用记录
4. **前端展示**: 创建全局的LLM调用记录页面,支持分页、倒序、筛选和详情查看

## 成功标准

- [ ] 数据库表正确创建,包含所有必要字段
- [ ] mcp.Client成功记录每次LLM调用(包括成功和失败)
- [ ] API接口返回正确的分页数据
- [ ] 前端页面能够展示LLM调用列表,支持分页和倒序
- [ ] 点击记录可以查看详细的输入/输出内容
- [ ] Token统计数据准确无误

## 非目标

- 不自动计算具体的花费金额(仅记录token数量)
- 不删除或修改现有的decision_logger功能
- 不涉及实时流式响应的记录(仅记录完整的API调用结果)
