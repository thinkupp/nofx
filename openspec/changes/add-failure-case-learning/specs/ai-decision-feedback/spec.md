## ADDED Requirements

### Requirement: 失败案例反馈

AI决策系统SHALL在生成交易决策时接收最近失败交易的详细案例，以避免重复相同错误。

#### Scenario: 展示止损失败案例

- **WHEN** AI系统调用buildUserPrompt()生成决策输入
- **THEN** User Prompt中包含"最近失败案例(避免重复)"章节
- **AND** 该章节展示3-5条最近的亏损交易案例
- **AND** 每条案例包含: 币种、方向(多/空)、入场价→止损价、亏损百分比、失败原因

#### Scenario: 失败原因分析

- **WHEN** 系统生成失败案例描述
- **THEN** 失败原因应基于可用的市场数据推断，包括:
  - 资金费率异常(如"资金费率0.08%过高")
  - 技术指标背离(如"假突破未确认")
  - 市场趋势反转
  - 杠杆过高导致被强平
- **AND** 如果无法确定具体原因，应标注为"止损触发"

#### Scenario: 失败案例数量控制

- **WHEN** 历史交易记录包含多于5条亏损交易
- **THEN** 仅展示最近5条亏损交易
- **AND** 优先展示亏损幅度较大的案例(>3%)
- **AND** 如果亏损交易少于3条，则展示所有亏损交易

#### Scenario: 无失败案例处理

- **WHEN** 系统没有历史亏损交易记录
- **THEN** 不显示"最近失败案例"章节
- **OR** 显示提示信息"当前无失败案例记录，继续保持良好表现"

#### Scenario: 失败案例格式化

- **WHEN** 生成失败案例文本
- **THEN** 使用简洁格式: "{币种}{方向}止损: {入场价}→{止损价}, {亏损%}, 原因:{原因描述}"
- **EXAMPLE** "BTC多单止损: 60000→59200, -5.2%, 原因:资金费率0.08%过高"
- **EXAMPLE** "ETH空单止损: 2850→2920, -4.1%, 原因:假突破未确认"
